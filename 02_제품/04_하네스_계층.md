# 하네스 계층 — JByond 구조 이식

- 작성일: 2026-08-20 (KST)
- 참조: `LSB-afk/JBFinAI-GoLAB-JByond` (JB금융 Fin:AI Challenge 본선작)
- 상위: `02_제품/03_개발_파이프라인.md`, `01_전략/04_스킬_구조.md`

## 1. 무엇을 가져왔는가

JByond를 클론해 띄워보고(`python3 -m http.server 8000 --directory app`) 확인한 결론은
이것이다.

> **그 구조의 값어치는 화면이 아니라, 운영 규칙을 실코드로 강제하는 계층에 있다.**

`app/harnessCore.js`가 정의한 것은 manifest 등록기, 훅 실행기, 가드레일 유틸,
자체검증 루프 넷뿐이고 업무 로직은 한 줄도 없다. 우리가 가져온 것도 그 넷이다.

가져오지 않은 것: 계열사·역할 축, scope 강제 repository, 해시체인 감사 원장,
Ollama 라우팅. 우리는 DB도 계정도 없고 저장하지 않기 때문에 들어올 자리가 없다.
**필요한 구성요소만 선택적으로 도입한다**는 원칙(HARNESS_GUIDE)이 그쪽 문서에도 있다.

## 2. 하네스의 단위 — 우리는 스킬 축이다

JByond의 하네스는 역할(전세보호·기업여신)과 계열사(JB우리캐피탈)다. 우리에겐
역할이 없다. 대신 **K-스킬이 곧 독립 업무 단위**다 — 자기 룰, 자기 기한, 자기
가드레일, 자기 골든셋을 갖는다.

| 하네스 | 스킬 | 룰 | 골든셋 |
|---|---|---:|---:|
| `payslip-audit` | 급여명세서 점검 | 11 | 17 |
| `departure-settlement` | 출국 정산 | 5 | 21 |

alias 하네스(main/default)는 만들지 않는다. 등록된 것이 전부다.

## 3. 파일

```
lib/harness/
  core.ts          manifest 등록 · 훅 실행기 · 훅 로그 · 자체검증   (엔진, 업무 로직 없음)
  guardrails.ts    G1~G7 — 이 도메인의 안전 규칙
  registry.ts      두 하네스 manifest
  harness.test.ts  16건
```

`lib/rules/` → `lib/ai/` 단방향 규율과 같은 이유로, `core.ts`에는 특정 스킬의
업무 상수를 넣지 않는다.

## 4. ★ 가드레일 — 이 계층의 진짜 값어치

이 서비스의 최대 위험은 틀린 계산이 아니라 **오탐의 대가를 근로자가 치른다는 것**이다.
E-9은 사업장 변경 횟수가 제한되고, 없는 돈을 약속하면 기대가 무너진다.
그래서 규율을 문서가 아니라 실행되는 코드로 옮겼다.

| # | 가드 | 막는 것 |
|---|---|---|
| G1 | 확정 표현 수준 제한 | "위법입니다"를 확인필요 판정이 쓰는 것 |
| **G2** | **수령불가에 금액 금지** | **없는 돈을 총액에 섞는 것** |
| G3 | 추정에 범위 강제 | 앞으로 받을 돈을 확정값처럼 제시하는 것 |
| G4 | 근거 조문 필수 | 조문 없는 지적 |
| G5 | 확인필요에 질문 필수 | "확인이 필요합니다"로 끝나 사용자가 막히는 것 |
| G6 | 개인정보 패턴 차단 | 판정 텍스트에 신원 정보가 새는 것 |
| G7 | 기한임박에 마감일 필수 | 급하다고만 하고 언제까지인지 안 알려주는 것 |

**G2와 G5가 실전에서 가장 중요하다.** 둘 다 "판정처럼 보이지만 사용자에게
아무 도움이 안 되는 출력"을 막는다.

### 문서가 아니라 테스트가 지킨다

`harness.test.ts`는 **국적 5종 × 시점 4종 × 근속 2종 = 40조합**의 실제 판정을
전 가드레일에 통과시킨다. 규율을 문서로만 적어두면 언젠가 어긋나는데, 여기서
깨지면 커밋 전에 잡힌다.

## 5. 훅

| 훅 | 하는 일 |
|---|---|
| `beforeJudge` | 입력 사전 검증 (지급 항목 유무 · 출국일 < 입사일 차단) |
| `afterJudge` | 가드레일 7종 전수 검사 |
| `beforeNarrate` | 판정 없이 3단으로 넘어가는 것 차단 |

**훅 로그는 순번(seq)만 쓰고 시각을 쓰지 않는다.** 시각을 넣으면 같은 입력에
다른 로그가 남아 재현성이 깨진다 — 심사자가 두 번 눌러 같은 결과를 봐야 한다.
`Date.now()`를 판정에서 걷어낸 것(`today` 주입)과 같은 이유다.

## 6. 실동작과 확장 예정을 분리한다

JByond의 "실동작 5 vs 확장 예정 9" 원칙을 그대로 가져왔다. manifest의 agent·command에
`live` 플래그가 있고, 콘솔이 그 수를 나눠서 표시한다.

| 하네스 | 에이전트 | 명령 |
|---|---|---|
| `payslip-audit` | 실동작 2 · 예정 2 | 실동작 3 · 예정 1 |
| `departure-settlement` | 실동작 2 · 예정 2 | 실동작 3 · 예정 1 |

예정을 실동작처럼 세면 그게 곧 과장이고, **기능명세서와 어긋난다.**
대회 규정이 "실제 구현된 기능만 작성"을 요구한다.

## 7. 자체검증

`runSelfTest(harnessId)` — 브라우저에서 즉시 돈다. 6종을 본다.

1. manifest 무결성 (필수 키 누락)
2. 훅 커버리지 (필수 훅에 핸들러가 있는가)
3. 에이전트 정합성 (실동작이 하나라도 있는가)
4. 룰 카탈로그 비어 있지 않음
5. 필수 고지 등록됨
6. **추정 룰 참조 무결성** — 카탈로그에 없는 룰 코드를 추정 룰로 지정하면 잡는다
   (오타 하나로 G3가 조용히 무력화되는 것을 막는다)

콘솔 본문 하단 `HARNESS VERIFICATION` 섹션에서 결과·에이전트·명령·훅 로그·필수 고지를
전부 볼 수 있다.

## 8. 검증 3계층

JByond의 "작업이 끝나면 세 계층을 모두 돌린다"를 우리 규모로 축소했다.

| 계층 | 명령 | 현재 |
|---|---|---|
| 단위 | `npm test` | **54건 통과** |
| 정적 | `npm run build` | 타입·빌드 통과 |
| 브라우저 | `/harness` 자체검증 | 점검 6종 통과 |

## 9. 화면 밀도 — JByond에서 가져온 두 번째 것

JByond 셸(`app/styles.css`)을 다시 읽고 확인한 것은 컬럼 수가 아니라 **동시에 보이는 양을 줄이는 장치**였다.

```
.app-shell { grid-template-columns: rail sidebar 1fr properties }
.app-shell.properties-collapsed  ← 속성 패널이 접힌다
.view-tabs / .segmented          ← 본문을 탭으로 쪼갠다
.panel-toggle[aria-expanded]     ← 섹션이 접힌다
```

우리도 같은 셋을 넣었다.

| 장치 | 적용 |
|---|---|
| 본문 탭 | 판정 · 입력 · 루프 · 근거 · 검증 — **한 번에 하나만** |
| 속성 패널 접기 | 상단 토글. 접으면 본문이 넓어진다 |
| 사이드바 축소 | 로고 클릭 → 60px 아이콘 레일 |
| 세부는 `<details>` | 룰 커버리지 · 기준값 · 훅 로그 · 필수 고지 |

**정보를 지운 것이 아니라 동시에 보이는 양을 줄였다.** 근거 문서 10종은 속성 패널에서 본문 `근거` 탭으로 옮겼다 — 그건 조작 손잡이가 아니라 참고 자료이기 때문이다. 속성 패널에는 라우팅 근거와 입력값만 남겼다.

## 10. 잠근 것

- 하네스 단위 = K-스킬. alias 하네스 금지
- `lib/harness/core.ts`에 업무 로직 금지
- 가드레일 G1~G7. 새 룰을 추가하면 40조합 테스트가 자동으로 검사한다
- 훅 로그는 순번만. 시각 금지
- agent·command는 `live` 플래그로 실동작/예정 분리

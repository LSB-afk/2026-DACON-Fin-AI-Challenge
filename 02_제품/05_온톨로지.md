# 온톨로지 계층 — T-Box와 A-Box

- 작성일: 2026-08-26 (KST)
- 상위: `02_제품/03_개발_파이프라인.md`, `02_제품/04_하네스_계층.md`
- 코드: `service/lib/ontology/schema.ts` (T-Box), `service/lib/ontology/abox.ts` (A-Box)

## 1. 왜 온톨로지인가

흐름도는 순서만 말한다. "무엇이 무엇과 절대 함께일 수 없는지"를 흐름도 어디에도
적을 수 없다. 이 서비스의 사고는 전부 **함께 있으면 안 된 것들이 함께 있는** 사고였다.

- 수령불가 판정에 금액이 섞였다 → 사용자는 못 받을 돈을 세고 공항에 간다.
- 확인필요 판정에 "위법입니다"가 섞였다 → 근거 없이 다투러 갔다가 돌아온다.
- 적용제외국 국적에 반환일시금 범위가 붙었다 → 존재하지 않는 700만 원을 약속했다.

그래서 개념의 계층·관계·제약을 코드로 들고 있다. 문서로 적으면 문구를 고치는
순간 조용히 풀린다. 코드로 적으면 테스트가 잡는다.

## 2. 두 파일 — T-Box와 A-Box

| | T-Box (`schema.ts`) | A-Box (`abox.ts`) |
|---|---|---|
| 담는 것 | 개념의 사전 — 클래스 66 · 관계 27 · 데이터 속성 13 · 공리 8 | 실행 한 번의 사전 — 발화·후보·국적·판정·금액·기한이 **개체**가 된 그래프 |
| 장치 | 모든 클래스·관계가 `파일:심볼`을 들고 있고, schema.test.ts가 readFileSync로 심볼 실재를 대조한다 | `buildRunABox()`가 판정 실행을 개체로 풀고, `validateABox()`가 T-Box에 대조한다 |
| 막는 것 | 화면과 문서가 코드에 없는 개념을 말하는 것 | 판정 결과가 온톨로지 어휘 밖으로 새는 것 |

T-Box만으로는 증명이 안 된다. 아무리 예쁜 스키마도 인스턴스가 없으면 장식이다.
A-Box가 실제 실행을 흡수해야 "이 온톨로지가 이 제품을 말해 준다"는 주장이 성립한다.

## 3. A-Box가 연결하는 선

`buildRunABox()`는 T-Box의 관계(ObjectProperty) 중 코드가 실제로 만드는 인과만 잇는다.

| 관계 | 의미 | 언제 놓이는가 |
|---|---|---|
| `p.routes` | 발화가 스킬 후보를 고른다 | 라우팅 결과가 있을 때 |
| `p.nationality-branches` | 국적이 S2-3 갈래를 정한다 | 출국 판정마다 |
| `p.unlisted-asks` | 명단 밖 국적은 되묻는다 | S2-3이 확인필요일 때 |
| `p.tenure-blocks` | 근속 미달이 수령불가를 낸다 | S2-1 수령불가 + 근속 12개월 미만 (시효초과 수령불가는 원인이 달라 잇지 않는다) |
| `p.today-fixes` | 기준일이 D-day를 정한다 | deadline이 붙은 판정마다 |
| `p.has-level / has-amount / has-range / has-deadline / cites` | 판정이 자기 산출물을 가진다 | 항상 |

잇지 않는 것도 기록한다: `p.size-downgrades`(규모 모름 → 확인필요 강등)는 Finding 안에
"어느 룰이 왜 이렇게 판정했는가"라는 원인 필드가 없어, 여기서 다시 추론하면 온톨로지가
판정 엔진을 흉내 내는 두 번째 구현이 된다. 원인 필드가 생기면 잇는다.

## 4. 검증기가 보는 것 — 공리 거울

`validateABox()`는 구조 검사(클래스·관계·속성의 domain/range 준수)와 함께 T-Box
공리를 개체 세계의 세 모양으로 재검사한다.

1. **없는 돈** — 수령불가 판정에 금액·범위 선이 있으면 위반 (공리 1·G2와 같은 사고)
2. **존재하지 않는 돈** — 적용제외국에서 갈라진 S2-3에 반환일시금 범위가 있으면 위반 (공리 5)
3. **functional(d.level)** — 판정 하나에 수준이 정확히 하나여야 한다 (공리 6)

골든셋 전부(`npm run verify`)와 단위 테스트(`lib/ontology/abox.test.ts`)가 매번
실제 판정을 그래프로 풀어 대조한다. 변형 그래프(수령불가에 700만 원 몰래 붙이기 등)를
넣었을 때 검증기가 침묵하는지도 테스트로 못 박았다.

## 5. 공리 강제 현황 — 7/8

2026-08-26: 공리 7(납부확인국 ∩ 적용제외국 = ∅)을 강제로 바꿨다.

- `constants-departure.ts:연금명단_교차검사()`가 세 국적 명단의 교차를 검사하고,
  departure.test.ts와 verify-golden.mjs가 매 실행마다 부른다. 겹치면 CI가 멈춘다.
- 이 공리가 막는 사고: 2차 출처를 믿고 베트남을 적용제외국에 넣을 뻔했던 일
  (`02_제품/02_S2_출국정산.md` 3절). 명단이 겹치면 연금납부여부의 앞 분기가 조용히
  이기고, 700만 원짜리 오답이 아무 경고 없이 부활한다.

남은 null 하나(공리 8 — 2차 출처 상수로 위법 단정 금지)는 일부러 남겨 둔다. 룰과
근거 문서의 검증 상태를 연결하는 provenance 계층이 아직 없는데, 없는 것을 강제되는
척하는 것이 이 저장소에서 최악의 상태다. schema.test.ts의 "null이 최소 1개" 테스트가
이 정직성을 지킨다.

## 6. 콘솔에서 보이는 것

루프 탭의 판정 뒤에 "온톨로지 · A-Box 대조" 단계가 붙는다. 개체 N개 · 관계 M개로
풀어 T-Box에 대조했다는 실측이 나오고, 위반 시 차단으로 표시된다. 산출물(JSON)에는
실행의 개체 그래프와 대조 결과가 함께 내보내진다 — 이 결과가 스키마 어휘로만 쓰였다는
증명이 결과와 함께 다니는 것이다.

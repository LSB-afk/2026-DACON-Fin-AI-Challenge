# Render Free 배포 · 제출 기간 접속 점검

필수 접근 기간: **2026-09-07 11:00 ~ 2026-09-11 23:59, Asia/Seoul**.
운영 여유 기간: 9월 12일 23:59까지. 공개 URL이 없거나 접근할 수 없으면 결격 위험이 있다.

이 구성은 무료 서버의 절전 가능성을 줄이는 **주기적 접속 점검**이다. 무중단 보장이 아니다. GitHub 예약은 지연·누락될 수 있고, Render Free는 임의 재시작·사용량 초과에 따른 중단이 가능하다.

## 1. 최신 GitHub 버전으로 무료 서버 생성

1. [GitHub main](https://github.com/LSB-afk/2026-DACON-Fin-AI-Challenge/tree/main)의 최신 커밋과 **Service CI 성공**을 확인한다. 로컬 미반영 파일이나 이전 ZIP으로 배포하지 않는다.
2. [이 저장소로 Render 배포 열기](https://render.com/deploy?repo=https://github.com/LSB-afk/2026-DACON-Fin-AI-Challenge)에서 로그인하거나, [Render Dashboard](https://dashboard.render.com)의 **New → Blueprint**에서 위 저장소의 `main`을 연결한다. 루트 `render.yaml`을 사용한다.
3. 생성 요약에서 **Web Service / Node / Free / Singapore**를 확인한다. 유료 인스턴스, 유료 DB, 디스크는 생성하지 않는다.
4. 다음 값은 Render에서 직접 입력한다. 채팅·GitHub 일반 변수·소스코드에 키를 넣지 않는다.
   - `ANTHROPIC_API_KEY`: 사용할 계정의 유효한 API 키.
   - `ANTHROPIC_MODEL`: 해당 계정에서 실제 사용 가능한 모델 ID를 명시한다. 코드의 기본 문자열만 믿고 생략하지 않는다.
   - `OLLAMA_URL`: 설정하지 않는다. 클라우드 서버에서 내 Mac의 localhost 모델에 접속할 수 없다.
5. 첫 배포 성공을 확인하고 **실제로 발급된** `https://…onrender.com` 주소를 기록한다. 이름 중복이면 다른 서비스 이름을 선택한다. 서비스 이름만 보고 URL을 추측하지 않는다.

| 항목 | 값 |
| --- | --- |
| 소스 | 이 저장소 `main`의 검증된 최신 커밋 |
| Root Directory | `service` |
| Build Command | `npm ci && npm run build` |
| Start Command | `npm run start -- --hostname 0.0.0.0 --port "$PORT"` |
| Health Check Path | `/api/health` |
| Node | `24.11.1` — CI와 동일 |
| Auto Deploy | Off |

서버는 `PORT`와 `0.0.0.0`에 바인딩한다. `/api/health`는 서버 생존만 검사하며, AI 장애로 Render 재시작이 반복되지 않도록 외부 API를 호출하지 않는다.

## 2. 배포 커밋과 실제 동작 검증

```bash
git fetch origin
git log -1 --format=%H origin/main
```

1. 위 40자리 SHA와 Render 배포 상세의 commit을 비교한다. 이후 새 커밋을 배포하려면 **Manual Deploy → Deploy a specific commit**에서 의도한 SHA를 선택한다.
2. `/api/health`의 `revision`도 같은 SHA여야 한다. Render의 `RENDER_GIT_COMMIT`을 사용하며 임의 값으로 덮어쓰지 않는다.
3. 아래 URL과 SHA를 실제 값으로 대체하여 점검한다.

```bash
cd service
EXPECTED_DEPLOY_SHA=배포된40자리SHA node scripts/smoke.mjs https://발급된주소.onrender.com
```

- `GET /api/health`: JSON · `status=ok` · `service=paycheck` · 캐시 금지 · 최신 시각 · 기대 SHA 일치.
- `GET /`: HTTP 200과 실제 「페이체크」 본문. 로딩 화면·리다이렉트·다른 사이트는 실패.
- `GET /api/agent`: HTTP 200과 AI 제공자·모델 설정. 미설정이면 실패.
- 요청·본문 읽기 타임아웃, 최대 3번 시도. AI POST, 자동 재배포, 자동 커밋은 하지 않는다.

**제공자 설정 확인은 키 유효성·잔액·모델 접근권한 확인이 아니다.** 공개 URL의 시크릿 창에서 합성 예시로 실제 상담 실행 → 추출값 검토 → 판정 → 승인 → 결과 적용을 확인하고 번역도 한 번 확인한다. 이 검증에는 AI API 사용료가 발생할 수 있다. 개인정보로 시험하지 않는다.

로컬에서 키 없이 HTTP만 확인할 때에만 `--allow-unconfigured-ai`를 쓴다. 루프백 주소에서만 허용되며 제출용 성공 근거로 쓰지 않는다.

## 3. GitHub 5분 점검 활성화

저장소 **Settings → Secrets and variables → Actions → Variables**에 일반 변수 두 개를 설정한다. 둘 다 비밀 키가 아니다.

| 변수 | 내용 |
| --- | --- |
| `RENDER_SERVICE_URL` | 실제 공개 `https://서비스명.onrender.com` 원점 주소. 경로·쿼리·로그인 정보 없음 |
| `RENDER_EXPECTED_COMMIT` | Render에서 검증한 배포의 40자리 SHA |

인증된 담당자는 CLI로도 설정할 수 있다.

```bash
gh variable set RENDER_SERVICE_URL --repo LSB-afk/2026-DACON-Fin-AI-Challenge --body 'https://발급된주소.onrender.com'
gh variable set RENDER_EXPECTED_COMMIT --repo LSB-afk/2026-DACON-Fin-AI-Challenge --body '배포된40자리SHA'
gh workflow run render-availability.yml --repo LSB-afk/2026-DACON-Fin-AI-Challenge --ref main
```

- Actions의 **Render availability**에서 수동 실행 성공·로그 SHA와 실제 예약 실행을 확인한다.
- 예약은 매시 03·08·13·…·58분이다. 실행 시각은 지연될 수 있다.
- UTC 9월 5~12일 cron과 코드의 **2026년·한국시간 경계**를 함께 검사한다. 자동 접속은 한국시간 9월 6일 00:00부터 9월 13일 00:00 직전까지만 수행한다. 기간 밖은 `SKIPPED`이며 정상 판정이 아니다. 수동 점검은 기간 밖에도 가능하다.
- URL 미설정 시 예약 job은 건너뛴다. 수동 실행은 설정 누락을 실패로 알린다. 파일을 GitHub에 올렸다는 것만으로 모니터링이 활성화되지는 않는다.
- 체크아웃용 `contents: read`만 사용한다. Render API 키나 AI API 키는 점검에 필요 없다.
- 종료 후 Actions에서 워크플로를 Disable한다. 운영 기간을 늘릴 때는 날짜 경계·cron·문서·Render 잔여 사용량을 함께 갱신한다.

## 4. 장애 알림과 독립 점검

1. GitHub 개인 **Settings → Notifications → Actions**에서 실패한 워크플로 이메일/웹 알림과 실제 수신 여부를 확인한다. 워크플로를 추가하는 것만으로 개인 알림 설정을 보장할 수 없다.
2. GitHub 예약 자체가 실행되지 않으면 실패 알림도 없다. 별도 외부 URL 모니터에 홈페이지를 등록하여 응답·본문과 장애/복구 알림을 확인하는 것을 권장한다. **이 저장소는 외부 모니터 계정이나 알림 채널을 자동 생성하지 않는다.**
3. 매일 공개 URL의 실제 상담·승인 흐름을 확인한다. GET 성공만으로 AI 잔액·권한 문제를 검출할 수 없다.
4. 장애·복구 시각, 실패 경로, Render 이벤트, 배포 SHA를 기록한다. 고객 입력·키·응답 전문은 공개 로그에 남기지 않는다.

## 5. 무료 한도 · 버전 고정 · 복구

- Render 무료 시간은 **워크스페이스 전체 월 750시간 공유**다. 다른 무료 서버와 합산하고, 켜 둔 시간이 계속 차감됨을 유의한다.
- 대역폭·빌드 한도도 확인한다. Free의 임의 재시작 제한은 ping으로 제거되지 않는다.
- 공개 GitHub 저장소의 표준 호스팅 러너를 사용한다. 비공개 전환이나 다른 러너 사용 시 무료 조건을 다시 확인한다.
- **서버 무료와 AI API 요금은 별개**다. 유료 자원 전환은 별도 승인 없이 하지 않는다.
- 심사 기간에는 Auto Deploy Off와 검증된 동일 URL·커밋을 유지한다. main이 바뀌어도 배포 SHA 변수를 자동으로 최신화하지 않는다.
- 복구는 Render의 직전 성공 배포 롤백 또는 검증한 특정 커밋 수동 배포로 한다. 확인 후 `RENDER_EXPECTED_COMMIT`을 실제 배포 SHA로 갱신한다. Git 이력을 되돌리거나 force push하지 않는다.
- 삭제·재생성은 제출 URL을 바꿀 수 있으므로 임의로 하지 않는다.
- 공개 URL과 검증된 commit, 점검 기록을 제출 문서와 제출 폼에 반영한다.

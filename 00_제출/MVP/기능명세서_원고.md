## 3. 아키텍처 — 3단 분리 (그림과 같은 서술: 화면 「판단 해설」 흐름도)

```
발화(사람) → 0단 라우팅(모델+키워드 기준선) → 1단 추출(모델, evidence 계약)
  → 2단 판정(순수 함수 — 모델 금지구역) → 가드레일 G1~G8 → 온톨로지 A-Box 대조
  → 답변 조립(결정적) → 3단 번역(모델, 숫자 보존 검증) 
```
- 단일 출처 `lib/flow.ts` — 화면 셋(흐름도·루프·Agent 타임라인)이 이 데이터를 참조,
  `flow.test.ts`가 1:1 일치를 강제
- 모델 출력은 전부 **계약**을 통과해야 화면에 나간다: 라우팅(스킬 ID 검증) ·
  추출(evidence 부분문자열) · 번역(줄 형식 + 숫자 다중집합 보존)

## 4. AI 모델 구성

| 자리 | 배포 | 로컬/내부망 | 실패 시 |
|---|---|---|---|
| 라우팅·추출·번역 | Anthropic API (`ANTHROPIC_API_KEY`) | Ollama (`OLLAMA_URL`, gemma4 8B 실증) | 해당 단계만 차단 표시 + 수동 입력/한국어 원문 폴백 |

- temperature 0 · 시한 제공자별(60s/180s) · 호출별 토큰·시간을 감사 원장에 기록
- **키가 없을 때의 데모**: 판정·가드·답변 조립·골든셋 등 화면 전부 동작,
  모델 단계만 "미연결" 정직 표기 — AI를 지워도 화면이 거짓말하지 않는다
- 개인정보: 주민·외국인등록번호/전화/계좌 꼴은 **전송 전 400 거부**(값은 응답에
  되돌려주지 않음) · 분당 20회/IP 제한(서버리스 인스턴스별 — 한계 명시) · 요청 ID 헤더

# 기획서 원고 — 페이체크 (PayCheck)

> 상태: **초안 (2026-08-28)** — hwpx 양식에 부을 원문이다. 모든 수치는 저장소 실측이며
> 각 수치 옆에 검증 명령을 적었다. 사람이 할 일은 맨 아래 체크리스트.

## 한 문장 정의

**페이체크는 한국에서 일한 외국인 근로자가 급여명세서와 출국 정산금을 법정 기준과
대조해, 확정과 추정을 구분한 금액·마감일·기관 제출용 근거를 돌려받는
"금융 접근 전(前)단계" AI Agent다.**

은행 계좌 개설이나 대출 승인을 약속하지 않는다. 그 전에 반드시 필요한 것 —
**자기 소득과 청구권의 증빙**을 복구해 준다.

---

## ① 서비스명·개요

- 서비스명: **페이체크 (PayCheck)**
- 형태: 모바일 우선 반응형 웹 (설치·로그인·업로드 없음)
- 구성: 근로자용 6걸음 화면 + 운영·검증 콘솔 16뷰(판정 근거를 심사자가 직접 검증)

## ② 추진 배경 — 문제는 언어가 아니라 판단이다

- 외국인 근로자 대상 **다국어 안내·번역 서비스는 이미 포화**다. 그런데 시효를 넘겨
  돈을 못 받는 일은 계속된다 — **증거(명세서·재직 기록)가 손에 있는데, 그것을 법정
  기준과 대조해 "얼마를, 언제까지, 어디에" 청구할지 판단해 주는 것이 없어서다.
- 출국 정산은 세 갈래(출국만기보험·귀국비용보험·국민연금 반환일시금)가 각각 다른
  주체·다른 기한을 갖는다. 보험 청구권 시효 3년(외국인고용법 §13④, 지나면
  한국산업인력공단 이전), 연금은 5년(국민연금법 §115). 국적 하나로 연금 수령
  가능 여부가 갈리고, 그 차이가 1인당 수백만 원이다.
- 금융 프레임: 급여명세서는 **소득 증빙의 관문**이다. 이것을 읽고 대조하지 못하면
  임금 정정 요구도, 기관 상담도, 금융기관 제출도 시작되지 않는다.

## ③ 서비스 내용 — 채널·흐름

- 1차 고객: **출국 또는 이직을 앞둔 E-9(고용허가제) 근로자** (H-2 포함)
- 핵심 순간: 출국 예정이 잡힌 날(≈30일 전), 그리고 급여명세서를 받은 직후
- 채널: 휴대폰 웹 — 외국인근로자지원센터·고용센터 **상담 전에** 혼자 확인하거나,
  상담사가 함께 화면을 보며 사용 (390px 실측 대응)
- 근로자용 화면 6걸음: ① 상황 입력(5칸, 신원정보 없음) → ② 확인 실행 →
  ③ 받을 돈(**확정·추정 분리 표기**) → ④ 마감일(D-day) → ⑤ 다음 행동(기관·연락처)
  → ⑥ 모국어 결과(베트남어·네팔어·크메르어·영어)
- 급여명세서는 **직접 입력 폼**(항목별 금액·근로시간 편집)으로 받는다. 값을 바꾸면
  판정이 즉시 달라진다. *사진(OCR) 추출은 로드맵이며 현재 기능이라 말하지 않는다.*

## ④ 차별화 — 번역이 아니라 대조 판단

| 기존 다국어 안내 | 페이체크 |
|---|---|
| 제도 "설명"을 번역 | **내 서류·내 조건을 법정 기준과 대조**해 숫자·기한으로 |
| 금액을 말하지 않음 | 확정 금액과 추정 범위를 **분리해** 제시 (합산 금지) |
| 상담 후 기록 없음 | 기관에 그대로 제출 가능한 **근거 장부**(룰·조문·산식 표시) |

구조적 차별점 — **판정은 모델 금지구역**: 라우팅·추출·번역만 LLM이 하고,
금액·기한 판정은 순수 함수 룰 16개가 한다(`npm test` 264건 · 골든셋 32케이스가
같은 코드로 매 실행 검증). 같은 입력이면 심사 중 언제 눌러도 같은 결과다.

## ⑤ AI 활용 — 입력·처리·출력로 나눈 정직한 서술

- **입력 단계 (AI)**: 자유 발화 → ⓐ 스킬 라우팅(키워드 기준선과 병렬 비교, 불일치
  시 되묻기) ⓑ 정보 추출 — 추출값마다 발화 원문의 **근거 스팬(evidence)** 을
  요구해 환각을 계약으로 차단. 필수값이 빠지면 **케이스 기본값을 쓰지 않고
  이유 붙은 질문으로 되돌린다.**
- **처리 단계 (AI 아님 — 의도적)**: 판정·가드레일 8종·온톨로지 대조는 결정적
  코드다. "AI가 판단한다"고 쓰지 않는 이유: 산수를 모델에 맡기면 같은 입력에
  다른 답이 나오고, 이 도메인에서 오답의 대가는 근로자가 치른다.
- **출력 단계 (AI)**: 조립된 한국어 답변의 **모국어 번역**. 원문의 모든
  숫자·날짜·조문이 번역에 그대로 없으면 **숫자 보존 검증**이 차단하고 한국어
  원문으로 폴백한다 (테스트로 고정).
- 제공자: 배포 Anthropic API · 로컬/내부망 Ollama(온프레미스 실증 — 어댑터 교체만).
  키가 없으면 화면이 "미연결"을 표시하고 판정·답변 조립은 그대로 동작한다.
- 운영 장치: 모델 호출 원장(토큰·시간·차단 사유), PII 입력 전송 전 차단,
  분당 요청 제한, 요청 ID.
- **사람 승인 게이트**: 추출값은 초안이다. 상담사가 근거 스팬과 대조해 인라인으로
  고치고 승인해야 판정·상담 기록으로 넘어간다(수정하면 승인이 풀린다). 기록에는
  추출값·수정 여부·승인 시각이 함께 남아, 모델이 한 일과 사람이 한 일이 구분된다.

## ⑥ 확장 계획 (로드맵 — 현재 기능 아님)

1. 급여명세서 **사진 추출(OCR/vision)** — 추출 결과는 지금의 편집 폼으로 들어와
   사람이 확정 후 판정 (기본값 금지 원칙 유지)
2. 지원 언어 확대(우즈베크어·태국어·인도네시아어 등 EPS 송출국) 및 화면 전체 다국어
3. 지원센터·고용센터 상담사용 **동석 모드**(상담 이력 없이 화면 공유 최적화)
4. 금융기관 제출용 **증빙 패킷 PDF** — 판정 JSON은 이미 내보내기가 되므로 서식화만
5. 금융권 내부망 배포 — Ollama 어댑터로 실증된 온프레미스 경로

## ⑦ (자유 주제) 검증이 승인자다 — 오답이 사람을 다치게 하는 도메인의 운영 체계

  모든 실행을 A-Box 개체 그래프로 풀어 어휘·공리 위반을 검사

  오답**(베트남 연금)을 공단 원문이 뒤집은 뒤, 국적 명단 교차검사를 CI에 박았다
- 근거 레지스트리는 검증 상태(원본확인 3 · 판례 1 · 2차출처 6)와 **원문 URL·확인일**을
  화면에 그대로 노출 — 숨기면 부채, 띄우면 할 일 목록
- 2026-08-28에도 같은 규율이 결함을 잡았다: 국민연금 **기준소득월액 상한 클램프
  누락**(고임금 과대 약속 위험)을 공단 공지 원문 확인 중 발견·수정·테스트 고정
